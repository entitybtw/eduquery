# Модели и движок

## Как это устроено

eduquery не содержит llama.cpp внутри образа. При первом запуске он:

1. определяет подходящий релиз llama.cpp (по умолчанию закреплённая версия, если GitHub API
   недоступен);
2. скачивает архив в `EDUQUERY_DATA_DIR/engine`, распаковывает `llama-server` и библиотеки;
3. при первом запросе к ИИ запускает `llama-server` на `127.0.0.1` со случайным портом;
4. загружает выбранный GGUF при первом обращении; смена модели/контекста перезапускает сервер.

Скачанные модели лежат в `EDUQUERY_DATA_DIR/models/<id>.gguf`. Недокачанные — `<id>.gguf.part`.

## Каталог

| id | Модель | Размер | RAM | Когда выбирать |
|---|---|---:|---:|---|
| `stories260k` | TinyStories 260K | ~1 МБ | 64 МБ | только проверить связку |
| `stories15m` | TinyStories 15M | ~19 МБ | 128 МБ | быстрый smoke-тест |
| `gemma3-270m` | Gemma 3 270M Instruct | ~250 МБ | 512 МБ | минимум, слабый русский |
| `qwen2.5-0.5b` | Qwen2.5 0.5B Instruct | ~490 МБ | 1 ГБ | слабое железо |
| `llama3.2-1b` | Llama 3.2 1B Instruct | ~810 МБ | 2 ГБ | разумный баланс |
| `qwen2.5-1.5b` | Qwen2.5 1.5B Instruct | ~990 МБ | 3 ГБ | лучшая из малых |
| `gigachat3.1-lightning` | GigaChat 3.1 Lightning (Q4_K_M) | ~6,5 ГБ | 8 ГБ | русский язык, нужно ≥ 10 ГБ контейнеру |
| `gigachat3-lightning` | GigaChat 3 Lightning (Q6_K) | ~8,8 ГБ | 10 ГБ | качественнее, нужно ≥ 12 ГБ |

Большая GigaChat 3 (702B) не входит в каталог: это многочастный GGUF на 150+ ГБ.

Подходит любой **instruct**-GGUF с chat template. Base-модели без шаблона работать не будут.

## Скачивание

- Каталог отдаёт `/api/v1/models/catalog`; установка — `POST /api/v1/models/download`
  с `{"id":"qwen2.5-0.5b"}`.
- Своя модель — `POST /api/v1/models/download/custom` с `id`, `name`, `url`.
- Загрузка идёт в фоне; прогресс виден в панели и в `GET /api/v1/models` (`downloads`).
- Одновременно можно качать разные id; повторный запуск того же id не создаёт вторую загрузку.

### Зеркала

Порядок адресов (`candidate_urls`):

1. `EDUQUERY_HF_MIRROR`, если задан: `https://huggingface.co/...` заменяется на
   `<mirror>/...`;
2. оригинальный адрес Hugging Face;
3. `https://hf-mirror.com/...`.

Пример:

```bash
EDUQUERY_HF_MIRROR=https://hf-mirror.com
```

Зеркало применяется только к записям встроенного каталога. Своя ссылка скачивается как есть.

### Докачка и проверки

- Файл пишется в `<id>.gguf.part`; при обрыве повторный запуск продолжает с места остановки
  (HTTP Range), а не начинает заново.
- После завершения проверяется сигнатура `GGUF` в начале файла.
- Размер сверяется с ожидаемым (для каталога); при сильном расхождении загрузка считается ошибкой.
- После успеха файл переименовывается в `<id>.gguf`, запись попадает в таблицу `models`,
  а первая скачанная модель автоматически становится активной.

### Остановка и остатки

- Активную загрузку можно остановить из интерфейса, не удаляя `.gguf.part`. После остановки
  модель видна как «недокачано N%» с кнопкой «Продолжить».
- При остановке интерфейс предлагает два варианта: сохранить остатки или удалить их.
- После перезапуска сервера или страницы панель находит `.gguf.part` и спрашивает, продолжить
  загрузку или удалить остатки.
- `DELETE /api/v1/models/{id}/partial` удаляет только недокачанный файл. `DELETE
  /api/v1/models/{id}` удаляет и `.gguf`, и `.gguf.part`, но только когда загрузка не идёт.
- Ссылка и имя своей модели сохраняются в настройках (`download_url:<id>`,
  `download_name:<id>`), поэтому докачка работает и после перезапуска.

## Активная модель

Активная модель — это путь к файлу, который получает запросы без явного `model_id`.
Она хранится в настройке `active_model_id` и восстанавливается при старте:

1. если сохранённый файл существует — он активен;
2. иначе выбирается первый найденный `*.gguf`;
3. если моделей нет — панель просит скачать модель.

При старте `ModelStore::reconcile` сверяет файлы на диске с таблицей `models`: найденные GGUF
регистрируются, записи без файла удаляются. Поэтому модель, скопированная в каталог вручную,
становится видна после перезапуска.

## Установка движка

`POST /api/v1/engine/install` (право `models`) запускает фоновую установку. Прогресс —
`GET /api/v1/engine/status`; в UI он показывается полосой сверху. Ошибка сохраняется и видна
в панели «Движок llama.cpp».

Переменные:

| Переменная | Значение |
|---|---|
| `EDUQUERY_ENGINE_VARIANT` | пусто — CPU, `vulkan` — GPU через Vulkan |
| `EDUQUERY_ENGINE_URL` | прямая ссылка на `.tar.gz` с релизом (зеркало) |
| `EDUQUERY_LLAMA_SERVER` | путь к своему `llama-server` |
| `EDUQUERY_ALLOW_REMOTE_DOWNLOAD` | `false` полностью запрещает скачивание движка и моделей |

## Офлайн-режим

1. Положите `llama-server` и его `.so` в `EDUQUERY_DATA_DIR/engine/`.
2. Положите GGUF в `EDUQUERY_DATA_DIR/models/`.
3. Установите `EDUQUERY_ALLOW_REMOTE_DOWNLOAD=false`.

После перезапуска файлы будут видны, активная модель восстановится.

## Память и производительность

- Модель целиком находится в RAM процесса `llama-server`; ориентируйтесь на `min_ram_mb` с запасом.
- `EDUQUERY_MEMORY_LIMIT` в compose ограничивает контейнер (по умолчанию `8g`). Для GigaChat
  Lightning нужно больше.
- `n_ctx` увеличивает память; для длинных характеристик поднимайте контекст постепенно.
- `n_threads = 0` — авто по числу ядер.
- Слабые модели склонны к повторам; DRY и `repeat_penalty` помогают, а `loop_detected` сообщает,
  что генерация была прервана.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «движок не установлен» | нажать «Установить» в панели или проверить `EDUQUERY_ALLOW_REMOTE_DOWNLOAD` |
| «модель не выбрана» | скачать и активировать модель |
| скачивание зависает | проверить MTU (`EDUQUERY_MTU`), сеть и зеркало |
| `llama-server` падает | повреждён GGUF, не хватает RAM или несовместимая сборка |
| модель повторяется | взять модель крупнее, поднять `repeat_penalty`/DRY, уменьшить `temperature` |
| каталог пуст | войти в систему и нажать «Обновить»; кэш восстанавливается из `localStorage` |
