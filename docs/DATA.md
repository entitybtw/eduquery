# Данные

## Где что лежит

```
EDUQUERY_DATA_DIR/
├── eduquery.db      # SQLite: пользователи, ученики, журнал, настройки, бенчмарки
├── models/          # *.gguf и *.gguf.part
└── engine/          # llama-server и библиотеки
```

По умолчанию в Docker это `/data`, при локальном запуске — `./data`.
Каталог `data/`, `*.gguf`, `*.db` и `.env` не входят в git (см. `.gitignore`).

## Схема SQLite

| Таблица | Назначение |
|---|---|
| `students` | ученики: `external_id`, ФИО, группа, e-mail, класс, `birth_date`, `address`, `family` |
| `activities` | записи журнала: тип, предмет, название, баллы, оценка, статус, время, дата, `details` |
| `models` | зарегистрированные GGUF: путь, размер, sha256, источник |
| `settings` | ключи `gen_params`, `active_model_id` и другие |
| `analyses` | история разборов с привязкой к ученику |
| `users` | логины, Argon2-хеши, роли, права, лимиты |
| `usage_log` | запросы к ИИ для лимитов |
| `sessions` | активные сессии |
| `benchmark_runs` | запуски сравнений: режим, промпт, системная инструкция, примеры, параметры |
| `benchmark_results` | ответы и метрики по каждой модели, ручная оценка |
| `usage_metrics` | журнал всех генераций: модель, источник, токены, скорость, время, ошибки |

### Миграции

Схема создаётся при старте через `CREATE TABLE IF NOT EXISTS`. Новые колонки добавляются в
`Db::add_columns` (проверка `PRAGMA table_info` + `ALTER TABLE`). Так обновление образа не требует
ручного вмешательства. Если колонка уже есть, миграция ничего не делает.

Незавершённые бенчмарки при старте переводятся в `error` с пометкой «прервано перезапуском
сервера»: после рестарта фоновой задачи уже нет.

## Записи журнала

Одна строка — одна запись. Типы (`kind`):

| kind | Что означает | Основные поля |
|---|---|---|
| `task` | домашняя работа | `subject`, `title`, `score`, `max_score`, `status`, `duration_min` |
| `quiz` | контрольная работа | то же |
| `submission` | проект | то же |
| `attendance` | занятие | `subject`, `duration_min`, `occurred_at` |
| `grade` | оценка 2–5 | `subject`, `grade` |
| `absence` | пропуск | `amount` (уроков), `reason`, `excused`, `subject` |
| `portfolio` | портфолио | `title`, `category`, `level`, `comment` |
| `behavior` | поведение | `category` (`Поощрение`, `Замечание`, `Нарушение`, `Нейтрально`), `comment` |
| `meal` | питание | `category` (завтрак/обед/полдник), `status` (`питался` / `не питался`), `level` (оплата) |

`status` работ: `выполнено вовремя`, `с опозданием`, `не выполнено`, `сдано`.
Пропуск: `excused` = `да` / `нет`; если пусто, причина определяется по тексту.
Уровни портфолио: `Школьный`, `Муниципальный`, `Региональный`, `Всероссийский`, `Международный`.

## Импорт

`POST /api/v1/import` принимает CSV или JSON, несколько файлов подряд. Разделитель `,` или `;`,
кодировка UTF-8 или Windows-1251, десятичная запятая допускается. `?mode=replace` очищает учеников,
активности и историю анализов перед импортом.

Колонки (русские названия; английские алиасы тоже принимаются):

`ID ученика`, `ФИО`, `Группа`, `Эл. почта`, `Дата рождения`, `Адрес`, `Семья`,
`Тип записи`, `Предмет`, `Название`, `Дата`, `Балл`, `Макс. балл`, `Оценка`, `Статус`,
`Время, мин`, `Пропущено уроков`, `Причина пропуска`, `Уважительная`, `Категория`,
`Уровень / оплата`, `Комментарий`.

Обязательно `ID ученика` или `ФИО`. Новый ученик создаётся по `external_id`; повторная строка
обновляет профиль и добавляет активность. Ошибки по строкам возвращаются в `errors`, импорт
продолжается.

Шаблон: `GET /api/v1/import/template.csv` или кнопка «Скачать шаблон» в интерфейсе.

## Экспорт

- `students.csv` — ровно текущая таблица с поиском, группой и сортировкой; включает дату рождения,
  адрес и семью.
- `activities.csv` — все записи в формате, который читает импорт.
- `analyses.csv` — история разборов.
- `benchmarks.csv` — запуски и ответы моделей.

CSV пишется в UTF-8 с BOM и разделителем `;`, чтобы Excel открывал файл без танцев.

## Демо-данные

`POST /api/v1/seed` (право `import`) пересоздаёт учеников и активности. Все данные **вымышленные**:

- город `г. Примерск`;
- улицы `ул. Школьная`, `ул. Лесная`, `ул. Солнечная` и т. п.;
- профессии без названий организаций: инженер, врач, учитель, водитель;
- родители и братья/сёстры — случайные вымышленные люди с согласованными фамилиями;
- e-mail в локальном демо-домене `@edu.local`;

Не добавляйте в `seed.rs` реальные школы, адреса, ФИО, работодателей, телефоны и ссылки на
личные страницы. Это публичный репозиторий.

## Резервная копия и обновление

1. Остановить контейнер.
2. Скопировать `EDUQUERY_DATA_DIR/eduquery.db` (при желании — весь каталог).
3. Запустить новый образ; миграции применятся сами.

Модели можно не копировать, если их не жалко скачать заново, но тогда после обновления активная
модель восстановится только после повторной загрузки.

## Удаление данных

- Ученик удаляется вместе с активностями и анализами (`ON DELETE CASCADE`).
- Запись журнала удаляется по `/api/v1/records/{id}`.
- Бенчмарк удаляется вместе с результатами.
- Полный сброс — остановить контейнер и удалить `eduquery.db`; при старте создастся пустая БД и
  первый администратор из переменных окружения.
