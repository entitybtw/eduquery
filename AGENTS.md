# eduquery

Локальная LLM-платформа для анализа учебной деятельности: веб-панель на Rust (axum), SQLite и
llama.cpp, который запускается на том же сервере. Данные учеников не уходят во внешние сервисы.

Начните с **`docs/README.md`**, затем открывайте только нужную страницу. Текущая очередь работ
лежит в **`docs/NEXT.md`**: этот файл не входит в репозиторий (git-ignored), но именно по нему
продолжается работа. Если файла нет (свежий клон) — скажите об этом, а не придумывайте задачи.

## Документация

Документация описывает **текущее состояние**, история — в git. Новое знание идёт на страницу
соответствующей темы; незавершённая работа — в `docs/NEXT.md`, завершённая — из `NEXT.md`
удаляется. Публичные страницы не ссылаются на `NEXT.md`.

**Документация публичная.** В ней не должно быть паролей, токенов, приватных адресов, реальных
IP, e-mail, названий организаций и работодателей, домашних путей. Пишите `$HOME`, `<сервер>`,
`<реестр>`. В примерах используйте только вымышленные данные.

## Быстрые команды

```bash
cargo check                     # типы и предупреждения
cargo build --release           # релизная сборка
EDUQUERY_DATA_DIR=./data ./target/release/eduquery   # локальный запуск
docker build -t <реестр>/eduquery:latest .
docker compose up -d --build
```

Полезные переменные: `EDUQUERY_DATA_DIR`, `EDUQUERY_ADMIN_USER`, `EDUQUERY_ADMIN_PASS`,
`EDUQUERY_ALLOW_ANONYMOUS`, `EDUQUERY_ALLOW_REMOTE_DOWNLOAD`, `EDUQUERY_HF_MIRROR`.
Полный список — в `docs/DEVELOPMENT.md` и `README.md`.

## Что важно не сломать

- **Каталог моделей** должен работать после входа, из кэша при недоступной сети и после
  перезапуска контейнера. Активная модель хранится в настройке `active_model_id` и
  восстанавливается при старте.
- **Докачка моделей**: файл `<id>.gguf.part` сохраняется, повторный запуск продолжает с места
  обрыва. После завершения проверяются сигнатура GGUF и размер.
- **Права**: чтение бенчмарков и моделей разрешено всем авторизованным; изменения моделей,
  параметров и запуск бенчмарков требует `models`; экспорт — `export`; профиль ученика — `import`.
- **Характеристика** — отдельный промпт, не «разбор для учителя». Не копировать пример дословно;
  факты брать только из данных ученика.
- **Семья и быт** входят в контекст ИИ, таблицу учеников, карточку, импорт/экспорт и характеристику.
- **Бенчмарк** идёт в фоне по одной модели, сохраняет ответы и метрики; одновременно допустим
  только один запуск.

## Проверка изменений

1. `cargo check` — без предупреждений.
2. `cargo build --release`.
3. Запуск с временным `EDUQUERY_DATA_DIR`, вход, демо-данные.
4. Проверить затронутые экраны и API; для ИИ — хотя бы одну реальную генерацию, если есть модель.
5. Убедиться, что в диффе нет `data/`, моделей, `.env`, персональных данных и секретов.

Подробнее — `docs/DEVELOPMENT.md`.
